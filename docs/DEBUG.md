# CubeKorean Debug记录

## 2026-09-03：IME组合中间态被误判为错误

- 现象：目标为 `커피` 时，输入第一个字母 `ㅋ` 会立即显示红色。
- 根因：程序直接用兼容字母 `ㅋ` 与完整音节块 `커` 比较。
- 修复：先把目标和输入音节拆解为兼容字母序列，再执行前缀判断。
- 验证：已人工验证 `ㅋ` 显示为正确，并由自动化覆盖 `ㅋ → 커 → 커ㅍ → 커피` 有效前缀。

## 2026-09-03：点击进入关卡后页面崩溃

- 现象：首页正常，点击“开始本关”后出现Runtime Error。
- 根因：重构判断逻辑时删除了变量 `target`，待输入字符渲染仍引用该变量。
- 修复：使用明确的 `expected` 保存当前目标音节。
- 验证：已在本地实际点击进入关卡并验证练习页面渲染；生产构建通过。

## 推荐排查顺序

```text
复现具体按键顺序 → 查看浏览器错误 → 区分IME中间态与最终值
→ 定位拼写纯函数或会话状态 → 运行相关测试 → npm run build
```

# 手机页面键盘反复唤起系统键盘

- 日期：2026-09-11
- 现象：手机未安装韩语系统键盘、改用页面韩语键盘后，每点击一个页面字母，系统键盘都会弹出。
- 原因：页面键盘的按键处理函数在每次输入后都调用隐藏文本输入框的 `focus()`，移动浏览器将该操作视为唤起软键盘的请求。
- 修复：页面键盘模式不再聚焦隐藏输入框，并设置 `readOnly` 与 `inputMode="none"`；切换到页面键盘时主动失焦，只有用户选择系统韩语键盘时才恢复聚焦。
- 回归：页面键盘仍通过内部字母序列组合韩文；系统键盘模式仍支持点击练习区域后恢复输入焦点。
